# پروتکل تست — ربات اسپرکت

> این سند را کنار دستتان باز بگذارید و **مرحله به مرحله** بروید.
> هر مرحله یک «معیار قبولی» دارد. اگر مرحله‌ای رد شد، **جلو نروید**
> و **پارامترها را تغییر ندهید.**

📄 گزارش کامل پژوهش: [`STRATEGY.md`](STRATEGY.md)

---

## ⚠️ قانون‌هایی که نباید بشکنید

| قانون | چرا |
|---|---|
| روی پنجره‌ای که دیده‌ایم تنظیم نکن | پنجرهٔ اخیر «دیده‌شده» است؛ تنظیم روی آن = آموزش به نویز |
| ایده‌سازی روی دادهٔ ۳ ساله ممنوع | با ۴۰۰ خانهٔ آزمون، یکی حتماً «خوب» به‌نظر می‌رسد — تصادفی است |
| اگر PF زیر ۱٫۳ آمد، پارامتر را دست نزن | اول بروکر/نماد/اسپرد را عوض کن، نه استراتژی را |
| تا پاریتی تأیید نشده، پولی وارد نکن | بدون پاریتی، بک‌تستِ شما دربارهٔ کدِ دیگری است |

## مرحلهٔ ۰ — نصب (۳ دقیقه)

1. در MT5: **File → Open Data Folder**
2. کپی کنید:

```
mql5/Experts/Esprakt_M1_LiquiditySweep.mq5  →  MQL5/Experts/
mql5/Include/Esprakt_RiskEngine.mqh         →  MQL5/Include/
mql5/Presets/Esprakt_US30.set               →  MQL5/Presets/
```

3. در **MetaEditor** روی فایل `.mq5` دوبار کلیک کنید و **F7** بزنید.

**معیار قبولی:** پنجرهٔ «Compile» سبز باشد و پیام
`0 error(s), 0 warning(s)` ببینید.

> ⚠️ این کد تا لحظهٔ نوشتن این سند **کامپایل نشده است** (محیط ساخت لینوکس
> بوده و MetaEditor ندارد). اگر خطا گرفتید، متن خطا را بفرستید تا درستش کنم.

## مرحلهٔ ۱ — پاریتی (مهم‌ترین مرحله)

تا وقتی ثابت نکرده‌ایم ربات همان کاری را می‌کند که پژوهش سنجیده، بقیهٔ
تست‌ها بی‌معناست.

### ۱-الف) عدد مرجع را بسازید (این روی کامپیوتر شما انجام می‌شود)

```bash
pip install --break-system-packages pandas numpy pytest
cd research
python3 -m pytest tests/ -q      # باید 19 تست سبز شود
python3 parity_check.py --symbol US30 --start 2023-09-04 --end 2023-09-15
```

خروجی: `research/results/parity/US30_trades.csv` — **۲۰ معامله** با زمان،
جهت، قیمت ورود/خروج و نتیجهٔ هرکدام.

### ۱-ب) همان بازه را در MT5 اجرا کنید

| تنظیم آزمونگر | مقدار |
|---|---|
| نماد | US30، تایم‌فریم **M1** |
| بازهٔ تاریخ | ‎2023-09-04 تا ‎2023-09-15 |
| مدل | **Every tick based on real ticks** |
| فایل ورودی | `Esprakt_US30.set` |
| `LiveTrading` | **false** (پیش‌فرض) |
| `Verbose` | **true** |

با `LiveTrading=false` ربات هیچ سفارشی نمی‌فرستد و فقط سیگنال‌ها را
می‌نویسد — هم در تب **Journal** و هم در یک فایل CSV در پوشهٔ `MQL5/Files`
با نامی مثل `esprakt_US30.csv`.

### ۱-ج) مقایسهٔ خودکار

```bash
python3 compare_parity.py --mt5 /path/to/esprakt_US30.csv \
                         --ref results/parity/US30_trades.csv
```

خروجی جدولی است که می‌گوید کدام سطرها یکی‌اند:

```
  ✅ یکی: 20/20   ⛔ جهت غلط: 0   ⚠️ قیمت غلط: 0   ⛔ پیدا نشد: 0
  🟢 پاریتی برقرار است (100٪) → بروید مرحلهٔ بعد.
```

| نتیجه | معنی | کار |
|---|---|---|
| 🟢 ‎≥ ۹۰٪ | پاریتی برقرار | بروید مرحلهٔ ۲ |
| 🟡 ۶۰–۹۰٪ | مشکوک | لاگ را بفرستید، ادامه ندهید |
| 🔴 ‎< ۶۰٪ | پاریتی نیست | **تست را متوقف کنید** |

### ۱-د) اگر خواستید دستی چک کنید

فایل `US30_trades.csv` را باز کنید و **۱۰ معاملهٔ اول** را با لاگ MT5 کنار هم

| ۵ | 2023-09-06 19:59 | SELL | 34455.00 | TP |
| ۶ | 2023-09-07 02:03 | BUY | 34438.97 | SL |

## مرحلهٔ ۲ — بک‌تست کامل ۳ ساله

همان تنظیمات، ولی بازهٔ کامل داده: ‎2023-08-01 تا ‎2026-09-21.

### عدد مرجع (پایتون، با هزینه‌های واقعی)

| | US30 | NAS100 |
|---|---|---|
| تعداد معامله | **۲٬۶۳۶** | **۲٬۷۳۸** |
| نرخ برد | ۴۸٫۶٪ | ۴۷٫۰٪ |
| امید ریاضی | **‎+۰٫۲۱۳ R** | **‎+۰٫۱۵۷ R** |
| ضریب سود (PF) | **۱٫۵۲** | **۱٫۳۸** |
| مجموع R | ‎+۵۶۲ R | ‎+۴۳۱ R |
| افت سرمایه | **‎−۶٫۵٪** | ‎−۱۰٫۶٪ |
| میانگین مدت نگهداری | ۸٫۴ کندل | ۸٫۴ کندل |

**معیار قبولی:** PF ≥ ‎۱٫۳ **و** تعداد معامله ≥ ‎۲۰۰.

**اختلاف طبیعی:** اگر تعداد معامله کمتر بود، نگران نباشید — اسپردِ
بروکر شما اگر از ‎۰٫۰۳ بازتر باشد، فیلتر «فاصلهٔ استاپ» معامله‌های بیشتری
را حذف می‌کند. **ولی اگر PF هم افت کرد، یعنی هزینه لبه را می‌خورد.**

---

## مرحلهٔ ۳ — پایداری (نیمیٔ اول در برابر نیمیٔ دوم)

بک‌تست را **دو بار** اجرا کنید: روی ‎۲۰۲۳-۰۸ تا ‎۲۰۲۵-۰۳ و ‎۲۰۲۵-۰۳ تا ‎۲۰۲۶-۰۹.

**معیار قبولی:** PF هر دو نیمه > ‎۱٫۲.

اگر یک نیمه خوب و دیگری بد بود ⇒ استراتژی روی یک «دوره» سوار بوده و
برای پول واقعی مناسب نیست.

> یادآوریِ پژوهش: در یک تست ۱۰سالهٔ مستقلِ ICT، نرخ برد ۶۱٪ و R:R مثبت
> بود ولی سرمایه از ۱۰۰ هزار به ۵۴ هزار افت کرد. **نرخ برد بالا دلیلِ
> سودآوری نیست.**

---

## مرحلهٔ ۴ — فشارِ هزینه

در آزمونگر، اسپرد را **دو برابر** کنید (یا `SlippagePoints` را زیاد کنید).

**معیار قبولی:** هنوز PF > ‎۱٫۱.

روی دادهٔ ما، طلا دقیقاً با همین آزمون رد شد (نسبت دامنه به اسپرد ۶ برابر
در برابر ۱۱۹ برابرِ شاخص‌ها). این مرحله همان چیزی را می‌سنجد.

---

## مرحلهٔ ۵ — دمو (حداقل ۲ ماه)

فقط حالا `LiveTrading` را روشن کنید — روی **حساب دمو**.

| معیار | حداقل |
|---|---|
| مدت | ۲ ماه کامل، بدون وقفه |
| سیگنال‌های دمو با بک‌تست یکی باشد | ‎≥ ۹۰٪ |
| افت سرمایه | زیر ‎۱۰٪ |

**تا وقتی این ۲ ماه تمام نشده، پول واقعی وارد نکنید.**

| مرحله | ریسک هر معامله | شرط عبور |
|---|---|---|
| ۱ | **۰٫۵٪** | ۶ ماه پاریتیِ پایدار |

## 🛠 اگر چیزی کار نکرد

| نشانه | علت محتمل | کار |
|---|---|---|
| کامپایل: `cannot open include` | هدر کپی نشده | `Esprakt_RiskEngine.mqh` را در `MQL5/Include/` بگذارید |
| کامپایل: `undeclared identifier` | ناسازگاری نسخهٔ MQL5 | متن خطا را بفرستید |
| صفر معامله | اسپردِ بروکر خیلی باز | `AutoSpreadATR` و `MinStopSpread` را ببینید؛ **اگر باز هم صفر بود، آن نماد مناسب این استراتژی نیست** |
| معامله هست ولی `TP` نمی‌خورد | `RR=1.5` با استاپِ ساختاری | طبیعی است — در مرحلهٔ ۲ درصدش را ببینید |
| سیگنال‌ها کاملاً متفاوت | اختلاف منطق | لاگ هر دو را بفرستید |
| «هیچ سطر سیگنالی پیدا نشد» | `Verbose=false` یا فایل اشتباه | هر دو را چک کنید؛ ربات باید کلمهٔ `BUY`/`SELL` بنویسد |
| `Journal` خالی است | `Verbose=false` | آن را `true` کنید |
